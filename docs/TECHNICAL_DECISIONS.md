# تصمیم‌های فنی پروژه بازار متل قو

## ۱. فناوری‌های اصلی
- **فرانت‌اند وب:** Next.js (App Router) + React + TypeScript.
- **استایل‌دهی:** Tailwind CSS (برای سرعت توسعه و طراحی واکنش‌گرا).
- **پایگاه داده و بک‌اند:** Supabase (PostgreSQL + Auth + Storage) به دلیل پلن رایگان و سادگی راه‌اندازی.
- **اپلیکیشن موبایل (آینده):** React Native + Expo (استفاده از گوشی واقعی به‌جای شبیه‌ساز به دلیل محدودیت رم ۶ گیگ).

## ۲. تصمیم‌های معماری مهم
- **قانون طلایی سبد خرید:** هر غرفه سبد خرید، سفارش و پرداخت مستقل دارد. این قانون در جدول `orders` با ستون `store_id` در دیتابیس قفل می‌شود، نه فقط در UI.
- **کمیسیون:** نرخ کمیسیون در لحظه ثبت سفارش به‌صورت Snapshot در همان رکورد سفارش ذخیره می‌شود. تغییر نرخ در آینده، سفارش‌های قدیمی را تغییر نمی‌دهد.
- **امنیت:** کنترل دسترسی‌ها (مشتری/فروشنده/مدیر) در سمت سرور و با قوانین RLS در Supabase اعمال می‌شود.
- **پرداخت:** مبلغ، تخفیف و کمیسیون فقط در سمت سرور محاسبه می‌شوند. به مقادیر ارسالی از مرورگر اعتماد نمی‌شود.
- **مسیر پروژه:** پوشه پروژه در `D:\my project\bazare-motelghoo` قرار گرفت تا از دسکتاپ و فایل‌های شخصی جدا باشد.
- **مونوریپو:** فعلاً از Turborepo یا Workspace استفاده نمی‌کنیم تا پروژه برای شروع ساده بماند و به رم ۶ گیگ فشار نیاید. این تصمیم هنگام شروع فاز موبایل بازبینی می‌شود.

## ۳. ابزارهای توسعه
- **ویرایشگر:** Visual Studio Code.
- **کنترل نسخه:** Git (نسخه محلی).
- **در آینده:** GitHub برای پشتیبان‌گیری آنلاین.
- **نصب نمی‌شود (فعلاً):** Docker, Android Studio, شبیه‌ساز اندروید.
## ۴. تصمیم‌های مربوط به بومی‌سازی (Localization)
- **واحد پول پایه:** تومان.
- **قابلیت سوییچ:** در پنل مدیریت، امکان تغییر واحد نمایش بین «تومان» و «ریال» وجود خواهد داشت. (در دیتابیس، مبالغ به یک واحد پایه ذخیره می‌شوند و تغییر واحد فقط در لایه نمایش اعمال می‌شود).
- **زبان رابط کاربری:** کاملاً فارسی و راست‌چین (RTL).
- **تقویم:** تاریخ‌ها در دیتابیس به میلادی (UTC) ذخیره می‌شوند، اما در رابط کاربری به صورت تقویم شمسی (جلالی) نمایش داده می‌شوند.
- **ساختار غرفه:** هر کاربر (فروشنده) فقط مجاز به داشتن **یک غرفه** است. این تصمیم برای ساده‌سازی فرآیند مالی و کمیسیون اتخاذ شد.
## ۵. تصمیمات فاز سبد خرید و سفارش
- **ذخیره سبد خرید:** فعلاً از `localStorage` استفاده می‌شود تا کاربر بدون لاگین هم بتواند سبد داشته باشد. ساختار داده به صورت آبجکت با کلید `storeId` است تا سبدها قاطی نشوند.
- **محاسبات مالی (در فاز بعدی):** مبلغ کمیسیون (پیش‌فرض ۱۰٪) در لحظه ثبت سفارش محاسبه و به صورت جداگانه در فیلدهای `commission_rate` و `commission_amount` در جدول `orders` ذخیره می‌شود (Snapshot).
